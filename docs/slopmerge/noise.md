# What gets skipped

Rules that keep reports to matches worth reading. All are applied before
scoring.

1. **IDF weighting** makes common statements count for little. It adapts to
   each codebase's own idioms.
2. **Minimum size.** After dropping docstrings, `pass`, `...` and bare
   `return`, a unit needs at least `--min-statements` statements and one
   that isn't common. A statement is common if it appears in more than 20
   shapes or 2% of them, whichever is more. `for x in y` / `yield x` /
   `return True` alone can't identify anything.
3. **Known boilerplate** is not matched as a unit (it can still appear
   inside a larger match):
   - bodies that only `raise NotImplementedError`, and abstract methods;
   - one-line delegations that forward their arguments;
   - property getters and setters of a single attribute;
   - `__init__` that only stores parameters (the class match covers it);
   - `__repr__`, `__eq__`, `__hash__` built only from attribute lists;
   - generated files: `*_pb2.py`, `*_pb2_grpc.py`, Alembic migrations, and
     files whose leading comments say "generated by", "auto-generated" or
     "do not edit". Only comments at the very top count, not docstrings.

   Everything skipped is counted in `stats.skipped`, by reason.
4. **Subsumption.** If a whole-function group is reported, matching blocks
   inside those functions aren't reported again. A class group lists its
   method matches inside itself.
5. **Overrides are not boilerplate.** Several subclasses implementing a
   method almost identically is a classic "move it to the base" candidate.
